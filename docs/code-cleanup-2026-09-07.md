# 代码深查与精简记录（2026-09-07，v1.6.7）

本轮在 `b01a1fb` 源码发布基线之上进行，整理为 [v1.6.7 干净源码发布](https://github.com/ansujuner/WebChat2api/releases/tag/source-v1.6.7)，使用独立的 `source-v1.6.7` 标签；不改写 `source-v1.6.6` 的原有下载包。代码检查和发布准备没有重启用户正在运行的应用、清空真实日志或使用真实供应商账号。

## 清理结果

- 删除 **52 个已确认不再使用的文件**：49 个应用源码模块、2 个旧 Vite 配置、1 个旧图标脚本。
- 应用 `src/` 源码新增 118 行、删除 8,911 行，**净减少 8,793 行**。新增测试和文档另计，不把锁文件缩短算成业务代码精简。
- 移除 8 个不再需要的直接依赖/类型声明依赖：`ali-oss`、`js-sha3`、`koa-router`、`recharts`、`@radix-ui/react-tooltip`、`canvas`、`@types/koa-router`、`@types/react-window`。
- 锁文件删除 **105 个依赖节点**；保留包的版本和完整性值没有变化。实际本地依赖目录也通过受控清理移除了 105 个包，依赖树检查正常。
- `form-data` 原本由传递依赖碰巧提供，现显式声明为运行依赖并保持内联，避免打包后出现缺模块。仍在使用的 `@koa/router`、`eventsource-parser`、`react-router-dom`、`react-window` 和 DeepSeek WASM 保留。

### 如何确认可以删除

从 Electron 主进程、preload、renderer 三个生产入口跟踪静态导入、动态导入、懒加载路由和重导出，并交叉核查调用符号、IPC 注册、脚本、测试、构建配置及文档。不是根据文件年代、`legacy` 字样或一次搜索无结果直接删除。

主要移除的旧实现：

- 已被 `ToolCallingEngine` 替代的旧 prompt adapters、variants、注入服务、客户端特征检测，以及未被调用的并行工具解析器。
- 已被实际 `appLogs` / `requestLogs`、`tray/TrayManager` 替代的旧日志、托盘和相关孤立工具模块。
- 已被 `AddAccountDialog`、当前供应商页面和 `RequestLog*` 替代的旧 OAuth、日志 UI、store、未使用页面容器和 UI 模板子组件。
- 不再使用的私有发送器、旧验证器、签名辅助方法、字段、局部变量和无意义状态。

旧配置和账户数据迁移、正常协议兼容入口、诊断命令、动态供应商注册、图标/WASM、许可及第三方声明均保留。账户工厂的旧测试改为调用真正的 `AccountManager.create`；旧流状态测试迁移到仍使用的兼容入口，而不是靠删除失败测试制造通过。

## 发现并修复的行为问题

### 请求日志界面

旧实现会让迟到的筛选结果覆盖新筛选，或在清空后被旧轮询重新显示已删除记录；清空 IPC 缺失时还会假装成功，拒绝时出现未捕获异常，重复点击可并行清空。

现使用请求版本判定、清空互斥、卸载清理和安全错误提示。**同一组 6 项回归在旧实现全部失败，新实现全部通过**；另经独立组合检查验证清空失败、筛选变化、卸载及迟到统计的组合。所有数据为隔离测试数据。

### 工具选择验证

此前 `tool_choice: "required"` 搭配空工具列表会被降级为普通请求；策略模块虽然有测试，却没有接入生产路径。现统一接入请求边界、两个客户端适配器和运行计划；必选工具为空、强制指定未声明工具会在账户选择、会话建立及上游提交前返回 **HTTP 400**。关闭工具处理模式也不会跳过输入验证。

### DeepSeek 非流式用量

旧分支判断错误的字段，累计用量 0 或 42 会错误回退成默认值 2。现按 `response` 下的 `accumulated_token_usage` 路径读取非负安全整数。**18 项用量回归**覆盖正文、完成状态前后/同批次顺序、运输拆包、最新累计值、非法值及错误路径。依据是已有协议处理路径和本地格式样本，不宣称本轮重新验证了官网计费。

## 防止问题重新进入

- 主进程目标设为 ES2022，主/前端采用独立 `noEmit` 检查，不再依赖会生成并遮蔽源码的声明输出。
- 两侧保留 `strict` 与 `noUnusedLocals`；不通过 `any`、忽略诊断或关闭严格检查来绕过问题。
- 新增 `npm run typecheck`，并让 `npm run build` 在打包前必须通过类型检查。原 16 项真实类型诊断所在不可达旧实现已移除；过时 target/项目引用带来的额外诊断也已解决。
- 新增 renderer 入口可达性、直接依赖声明、打包内联、类型配置和异步生命周期回归。
- 源码残留检查不再重复遍历，也不会扫描本地审计副本、报告和覆盖率输出。
