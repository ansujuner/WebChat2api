# v1.6.5：供应商独立代理与已有账号重新登录

以下说明适用于重新构建并启动后的 v1.6.5。它不表示正在运行的旧版本已更新，也不是所有真实账号、代理或模型均已验证可用的报告。

## 每个供应商分别选择网络

在 **供应商 → 对应供应商卡片 → 供应商网络** 中设置。内置与自定义供应商都可单独选择；修改其中一个不会改动其他供应商。

| 界面选项 | 行为 |
| --- | --- |
| 跟随全局默认 | 继承“设置”中的全局网络默认设置；旧配置未指定独立模式时保持此行为。 |
| 使用系统代理 | 使用 Windows/Chromium 的系统代理与 PAC 规则，不会自动开启代理软件。 |
| 不使用代理（直连） | 此供应商直接连接，不跟随系统或全局代理。 |
| 指定代理 | 为此供应商填写明确的 HTTP、HTTPS 或 SOCKS5 代理地址，然后点击“保存指定代理”。 |

指定代理地址必须包含协议、主机和端口，例如 `http://127.0.0.1:7890`、`socks5://127.0.0.1:7891`。这些只是格式示例，**不代表本机已在这些端口运行代理**。应填写代理软件实际提供的地址，而不是供应商网站或本应用的 API 监听地址。

无效地址会被拒绝，保留原已保存设置；不允许用户名、密码、路径、查询参数、片段、PAC 脚本或多条代理规则，也不会因配置错误悄悄回退直连。指定模式还需代理服务本身已运行且能够访问目标。

独立设置覆盖该供应商的登录、账号验证与测活、模型列表和聊天出站请求。**保存仅影响后续新请求/新登录操作，不主动中断进行中的回答。** 若账号或浏览器正在处理操作，先等待完成。不要为了切换代理重复提交尚未结束的消息。

**Arena 的额外边界**：应用无法仅凭 API 空闲判断可见浏览器中的手动聊天已经结束。因此，代理设置保存后，仍存活的 Arena 浏览器不会被自动关闭或热重启；新操作返回 `route_changed` 并停止，不会继续走旧路由。请先等官网手动聊天结束，手动关闭该 Arena 浏览器窗口，再重新操作。只有确认原浏览器已退出，才会以原配置目录和新代理重新打开，不创建空白账号配置。

### “检查代理规则”不是连通性测试

按钮只解析当前目标的路由选择，不发送聊天、不验证账号，也不证明代理服务器可用。

- `proxy`：规则选择了代理，仍可能因代理未启动、连接失败或网站限制而无法访问。
- `direct` / `DIRECT`：规则选择直连。**Windows 系统代理关闭且没有生效的 PAC/自动代理规则时，选择“使用系统代理”仍会得到 DIRECT**。安装了代理软件不等于系统已启用它。
- `unknown`：本次无法确定路由，不能据此认定已走代理。

系统/PAC 也可能只让部分目标直连。若需要强制某个供应商使用本机代理，可选择“指定代理”，不必改动 Windows 系统设置。

## 已有账号重新登录：不再另建一条账号

在对应供应商的账号卡片点击 **重新登录**。已有内置账号均有入口；非 Arena 账号仍保留“手动输入”页签。

1. 在官网窗口使用与原记录相同的账号，手动完成网站要求的登录或验证。
2. 主进程核对身份，只有确认匹配后才将凭据更新自动保存到**原账号 ID**；无需再点击“保存更改”来保存登录凭据。
3. 等待明确显示“登录已恢复”或“凭据已更新并保存”，再从账号列表按需测活。仅打开窗口、取得令牌、检查路由或网页显示已登录，都不等于真实聊天已通过。

重登不会新建账号，也不会更改自定义名称、手动启停、冷却、使用额度等设置；原凭据认证错误只有经过相应身份验证才更新。不同身份、账号已删除或凭据已被其他操作替换时，旧登录结果不能覆盖当前记录。未手动修改凭据的编辑表单，在之后保存名称/额度时也不会把旧令牌写回。

- **Arena**：复用此账号原有的 `browserProfileId` 和应用专属浏览器配置，不创建空白配置、不导入个人浏览器资料。已登录时核对原身份，已退出时在原窗口登录。若窗口切到了其他账号，拒绝替换原记录，聊天提交前也会核对配置与身份。
- **Z.ai**：继续使用已保存的账号凭据尝试恢复其应用专属官网窗口；核对官网身份后自动保存，窗口保持打开。网页认证和发送消息时的独立验证码不是同一个检查。
- **其他内置供应商**：使用各自登录流程；有些窗口在验证完成后关闭。新凭据必须能与原身份核对，不能只根据显示名称认定是同一账号。
- **旧记录身份不足**：如果原凭据失效，或者供应商不返回可核对的邮箱/用户 ID，界面会明确说明未替换。非 Arena 账号可在“手动输入”中更新同一账号的凭据，再验证；不会为了显示成功而猜测身份。Arena 则先在原账号浏览器窗口完成登录。
- **自定义 API 账号**：入口叫 **更新凭据**，用于修改 API Key 等字段并显式保存，不伪装成网页 OAuth 登录。

若已手动编辑但尚未保存凭据，先保存这些更改再重新登录；不会无提示丢弃手填内容。关闭编辑页不等于取消主进程中的登录流程；应以最终结果或官网窗口的关闭/取消为准。重新登录不解除账号冷却或保证验证码、网站限制、旧网页聊天状态恢复。

账号名称仍优先使用服务商返回的邮箱，没有邮箱时使用用户 ID 或独立本地编号；自定义名称与列表短账号 ID 保留。无需清空账号数据。

## 只读诊断命令

先打开当前项目的新版应用，然后运行：

```powershell
.\scripts\check-local.ps1 -Network
```

该模式与 `-Live` 及其他检查模式互斥。它把任务交给已运行的应用，只读取供应商设置并解析路由；不读取账号凭据、不生成聊天、不启动登录浏览器、不修改 Windows 设置，也不会为了检查而启动本地 API 代理。

项目运行时报告保存为 `artifacts/proxy-network-probe.json`。报告中的 `source` 是供应商选项，`mode` 是解析后的有效模式，`route` 为 `proxy`、`direct` 或 `unknown`；`resolutionOnly: true` 明确说明这不是连通性检测。`completed` 只表示完成了路由解析，不代表真实账号或模型可用。报告不包含代理地址、账号资料、凭据或响应正文。

## 让新版生效

先等待正在进行的请求结束并完成或取消登录，在 **WebChat2api 托盘菜单选择“退出”**，然后在项目目录运行：

```powershell
.\scripts\start-local.ps1 -Build
```

启动器检查运行中的项目进程；不会强制关闭应用，也不会清空账号或修改 Windows 系统代理。已有供应商未选择独立模式时继续跟随原全局默认。如启动器要求更新项目锁定的 Electron 内核，再使用 `-UpdateRuntime -Build`。实际启动与安全重启步骤见 [本地部署说明](./local-deployment.md)。

应用使用真实浏览器内核，不伪造指纹、不关闭 TLS 检查或登录沙箱。设置页显示实际运行内核；新内核并不保证供应商不再要求验证。

## 验证与边界

- `npm test`：单元、模拟服务商和协议回归。
- `npm run build`：生产构建。
- `node scripts/smoke-app.cjs`：生产 Electron 的隔离应用验证，使用工作区内全新账号目录、随机本机端口与合成官网响应；不会读取你的账号或操作正在运行的正式应用。结果保存于 `artifacts/runtime-app-smoke.json`。其中合成重登边界只验证界面保存行为，不当作真实供应商身份验证。
- `artifacts/network-electron-runtime.json`：真实 Chromium 本地代理转发、直连、账号 Cookie 隔离、上传、压缩与流式验证记录。没有修改用户的系统代理。

自动化和本地模拟通过都不代表真实网站已经接受登录或生成。Perplexity 的旧 OAuth 适配器仍仅检查 Cookie 是否存在，缺少可核对身份时不能当作安全自动重登成功。真实账号登录、代理连通性和模型调用需分别确认；遇到官网验证应正常手动完成，不自动绕过或重发生成请求。
